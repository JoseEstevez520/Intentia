### 2. Sistema de Triggers (zonas invisibles)

**Archivos nuevos:**
- `models/Trigger.java` — modelo de trigger
- `entities/TriggerManager.java` — carga y chequeo

**Cómo funciona:**
1. En Tiled se crea una capa de objetos llamada `"Triggers"`
2. Se dibujan rectángulos con propiedades:
   - `triggerType`: `"dialog"` | `"flag"`
   - `dialogNodeId`: nodo de historia a disparar (si type=dialog)
   - `flagName`: flag a dar (si type=flag)
   - `oneShot`: `true` / `false` (por defecto false)
3. GameScreen carga los triggers al iniciar el mapa
4. Cada frame, TriggerManager.checkTriggers() comprueba si el jugador solapa algún trigger
5. Si el trigger es tipo "dialog" → se abre DialogOverlayScreen con ese nodo
6. Si es tipo "flag" → se da el flag silenciosamente
7. Los triggers oneShot se persisten en GameState.flags (como `trigger_BeginningFields_200`)

**Integración en GameScreen:**
- `TriggerManager triggerManager` — nuevo campo
- Se carga después de los NPCs en `show()`
- `checkTriggers()` se llama en `render()` antes de `manejarInteraccion()`
- Al activarse un trigger DIALOG, usa el método auxiliar `abrirDialogo()`
- Al cerrarse el diálogo, se rearma el trigger con `rearmTrigger()` (si no es oneShot)

### 3. Sistema de Diálogo Condicional (NPC con memoria)

**Archivos nuevos:**
- `dialog/DialogRule.java` — modelo de regla condicional
- `dialog/DialogRouter.java` — resuelve qué nodo mostrar según flags
- `assets/dialog/dialog_routes.json` — reglas en JSON

**Cómo funciona:**
1. Cada NPC tiene un `dialogNodeId` por defecto (el de siempre)
2. El `DialogRouter` tiene un mapa de reglas por NPC
3. Cuando hablas con un NPC, el router evalúa las reglas en orden:
   - Primera regla que cumpla la condición → usa ese nodeId
   - Si ninguna regla cumple → usa el nodeId por defecto
4. Las reglas se definen en `dialog_routes.json`:
```json
{
  "abuelo": [
    { "check": "flag", "flag": "tiene_brujula", "nodeId": "npc_abuelo_examen" },
    { "check": "default", "nodeId": "npc_abuelo_hola" }
  ]
}
```

**Integración:**
- `Main.java` carga el `DialogRouter` en `create()` y lo expone vía getter
- `GameScreen.manejarInteraccion()` usa `game.getDialogRouter().resolve(npcId, fallback)` en vez de `npc.getDialogNodeId()` directamente

### 4. Bugs corregidos

- **Línea vertical en el centro del mapa**: causada por la cámara en posiciones sub-pixel (float) después del `lerp`. Solución: redondear la posición de la cámara a enteros tras el lerp (`Math.round`).
- **NPC.java — variable color no definida**: error preexistente donde el segundo constructor usaba `color` sin tenerlo en scope. Solucionado moviendo la llamada a `crearPlaceholder` al primer constructor.
- **Diálogo con ESC mostraba "FIN DEL PROLOGO"**: porque el DialogOverlayScreen se creaba sin `startNodeId` y el storyManager estaba al final. Solucionado con `irAPausaDirecto()` que salta directo al menú de pausa sin pasar por la historia.

### 8. Notas técnicas importantes

- La capa `"Triggers"` debe existir en el .tmx para que los triggers funcionen. Si no existe, TriggerManager no hace nada (log).
- Las propiedades de Tiled se leen como strings siempre. Los boolean se parsean con `Boolean.parseBoolean()`.
- El `DialogRouter` se carga al iniciar el juego. Si el JSON falta o está mal, se crea un router vacío (todos los NPCs usan su nodeId por defecto).
- Para añadir triggers al mapa actual: abrir Beginning Fields.tmx en Tiled, añadir capa de objetos "Triggers", dibujar rectángulos con propiedades.
- El `oneShot` de los triggers se persiste en GameState.flags con ID `trigger_{mapName}_{objectId}`.
- La resolución del juego es 640x360 (FitViewport). Los tiles miden 16x16.

### 9. Sesión extendida — Sistema de NPCs + Sprites Pokémon FR/LG

#### 9.1 Sistema de NPCs completo

**Arquitectura (sin Ashley ECS):**
```
entities/
├── Direction.java       ← Enum: ABAJO, ARRIBA, IZQUIERDA, DERECHA
├── NPC.java             ← Entidad NPC con IA, animación, interacción
├── NpcManager.java      ← Carga NPCs desde Tiled "NPCs" layer o defaults
└── Player.java          ← Jugador, input, animación
```

**NPC.java — características:**
- 4 tipos de movimiento: `STATIC`, `PATROL_H`, `PATROL_V`, `WANDER`
- 3 estados: `IDLE`, `WALKING`, `TALKING`
- Carga sprites desde `sprites/npc/` (fallback a rectángulos de color)
- Interacción por tecla E con radio de 40px
- Al hablar: setTalking(true) congela al NPC

**Movimientos:**
- `STATIC`: quieto, animación idle
- `PATROL_H/V`: va y viene entre `origin ± patrolDistance`, con pausa de 2s al llegar
- `WANDER`: dirección aleatoria, camina 1-3s, pausa 2-4s, repele en bordes (32-600px)

**NpcManager.java:**
- `loadFromTiledLayer(TiledMap, String)` — lee capa "NPCs" del .tmx
  - Propiedades: npcId, dialogNodeId, movement, speed, patrolDist, color, spriteWalk, spriteIdle
- Si no existe la capa, carga defaults hardcodeados (3 NPCs)
- Y-sort por posición Y cada frame (para orden de renderizado correcto)
- `getInteractiveNPC(Vector2)` — detecta NPC cercano para interacción

#### 9.2 Sprites — Pokémon FireRed/LeafGreen (3ª generación)

**Fuente:** Spriters Resource asset 3698
- URL: https://www.spriters-resource.com/media/assets/4/3698.png
- Dimensiones: 238×2967 px
- Fondo blanco (255,255,255). Sprites sobre naranja #FF7F27.
- Cuadrícula: filas blancas separan personajes, columnas blancas separan frames

**Estructura por personaje (1 fila = 1 personaje = 24px alto):**
```
13 frames: [DOWN×3][UP×3][LEFT×3][RIGHT×3][WAVE×1]
Cada frame: 16×24 px con fondo naranja #FF7F27
```

**Extracción (script Python):**
1. Detectar filas blancas (<15px no-blancos) → separan personajes
2. Detectar columnas blancas (0px no-blancos) → separan frames
3. Cada celda entre separadores = 1 frame
4. Recortar cada frame a su bounding box no-blanco
5. Hacer transparente solo el blanco puro (255,255,255)
6. Redimensionar a 32×48 con NEAREST (escala ×2)
7. Spritesheet final: 4 filas × 2 columnas (128×192 walk, 32×192 idle)

**Asignación final de personajes (desde Char 1 = Red):**
```
Char 21 → prota (niño)  — sprites/npc/prota_walk.png
Char 22 → mujer_c (madre) — sprites/npc/mujer_c_walk.png
Char 23 → hombre (padre)  — sprites/npc/hombre_walk.png
Char 25 → abuelo          — sprites/npc/abuelo_walk.png
```

**Orden de filas en spritesheet:**
```
Fila 0 = ABAJO
Fila 1 = ARRIBA
Fila 2 = IZQUIERDA
Fila 3 = DERECHA
```

**Bugs de animación corregidos en NPC.java:**
1. `tiempoAnimacion` se actualizaba ANTES de la máquina de estados → causaba frame fantasma en transiciones IDLE↔WALKING. **Fix:** mover la máquina de estados antes de `tiempoAnimacion`.
2. `crearCaminar()` añadía TODOS los frames (4), pero solo los 2 primeros tienen sprite. Los frames 2-3 vacíos causaban desaparición cíclica. **Fix:** solo usar frames[0] y frames[1].
3. `actualizarPatrolH/V()` snappeaba la posición al límite (`position.x = target`) → causaba teletransporte. **Fix:** usar lerp suave (`t = 1 - walkTimer/duracionTotal`).
4. `actualizarWander()` no tenía límites → la madre se iba del mapa. **Fix:** clampear a 32-600px y cambiar a IDLE al llegar al borde.
5. `batch.setColor(1,1,1,1)` redundante → eliminado.

#### 9.5 Notas técnicas importantes

- La capa `"NPCs"` en Tiled debe tener objetos con propiedades: `npcId`, `dialogNodeId`, `movement`, `speed`, `patrolDist`, `spriteWalk`, `spriteIdle`, `color`
- Si un NPC no tiene sprite (fallback), se muestra como rectángulo de color
- Los NPCs se renderizan ENTRE capas de fondo y capas frontales del mapa
- Para cambiar de mapa: crear una `GameScreen` con la ruta del .tmx diferente
- El `NpcManager.loadFromTiledLayer()` se llama desde `GameScreen.show()`
- La interacción con NPC usa `npc.getInteractionBounds()` que es un rectángulo extendido
- Los diálogos NPC se almacenan en `intentia.db` con IDs como `npc_abuelo_hola`, `npc_abuelo_despide`
